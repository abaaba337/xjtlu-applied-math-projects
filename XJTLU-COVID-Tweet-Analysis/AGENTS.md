# 项目维护规则

先读 `README.md` 路线表和 `data/README.md` 输入输出关系，再修改对应笔记本。

- 默认 `ponytail full`：读实际调用链后，按需求必要性、仓内复用、标准库、原生能力、已有依赖、一行实现、最小实现的顺序选择方案。
- 路径集中在 `project_paths.py`；共享数值函数在 `analysis_utils.py`。修改共享函数前搜索所有笔记本调用方。
- T2 只分析推文，地方新闻在 N2/N3；不混用语料、停用词、模型或向量器。
- 保留词性列差异、FIPS 前导零、日期排序、连接基数检查和时间窗口定义。缺失值不等于零。
- 不擅自改变研究参数、人工政策修正、过滤阈值或 KL 定义；只修复可验证的实现错误。
- 不提交笔记本执行输出、实验数据、模型、环境或凭据；运行写文件步骤时使用独立数据副本。
- 非平凡修改保留能检出回归的最小检查；执行 `python -m pytest -q`、`git diff --check`，并按 `ponytail-review` 审查当前 diff。
- 区分语法检查、人工小样本回归和真实数据复现。缺数据、环境或服务时明确报告。

`CLAUDE.md` 通过 `@AGENTS.md` 引用本文件。
